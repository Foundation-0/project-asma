00//The question

Chowdhury et al., Cell 2023

One published result, rebuilt from scratch.

High-grade serous ovarian cancer (HGSOC) is the most common and most lethal form of ovarian cancer. First treatment is usually platinum chemotherapy. Some tumours never respond at all. That is primary refractory disease, and it is not the same as cancer that responds first and resists later.

In 2023, Chowdhury and colleagues published a proteogenomic study of HGSOC. Among its results was a signature: levels of 64 proteins, measured in tumour tissue, that separated refractory from sensitive cancers in the study's own data. The headline measure was an AUC of 0.83. At the study's strictest operating point it caught about a third of refractory tumours (sensitivity 0.35) while almost never flagging a sensitive one (specificity 98%).

A result like that matters only if it survives outside the data it was built on. Project Asma's first pilot takes the published panel exactly as printed and asks whether the reported numbers can be recovered from the public data, and whether the patients counted as a separate validation group really are separate. It does not build a new test, and it makes no claim about patient care.

02//The number

preliminary · arithmetic only

0.81 where the paper prints 0.83.

AUC is a ranking score. Take every refractory patient and pair them with every sensitive patient: the AUC is the share of pairs where the refractory patient has the higher score, with tied scores counting half. 1.0 ranks every pair correctly; 0.5 is no better than chance.

The published supplements carry a score for each of the 135 discovery patients. Pairing the 52 refractory with the 83 sensitive patients gives 4,316 pairs. The released scores rank 3,491 of those pairs correctly and none are tied, so the AUC of the released scores is 3,491 / 4,316 = 0.80885, which rounds to 0.81. The paper prints 0.83. The gap, 0.0211, is just outside the 0.02 agreement margin the pilot set before running the check.

Score direction cannot explain the gap. The specification reads the scores as the probability of refractory disease, following the paper's methods text. Read the other way, the same scores give 0.191, much further from 0.83.

What this does not show. It does not show the paper is wrong. The printed 0.83 is itself rounded, and its unrounded value is not available. The released scores have not been shown to be the exact predictions the printed value was computed from; the paper's figure code averages predictions over 100 repeated splits, and no export connects that object to the released workbook. A mismatch between a printed value and a later file release is a provenance question, and it stays open until the authors' original inputs surface.

03//Still missing

gates before any refit

Four gaps stand between here and a reproduction.

The fold helper

The authors' scripts call a helper file, balanced_folds.R, that is not in their repository, its history, or its forks. It decides how patients were split into folds, so the printed cross-validation cannot be rerun faithfully without it or a declared replacement.

The workspaces

The figure scripts load saved R workspaces (RData files) that were never released. Which objects they held, and in what order, decides what the printed figure actually averaged.

The corrected legends

A 2024 correction fixes the supplemental figure legends, and the released Figure S3 legend disagrees with the article's own references at several points. Which legend is authoritative has to be settled before a reproduction target can be frozen.

People and permissions

No gynaecologic oncologist or proteomics/biostatistics collaborator has been recruited, and the repository licence is undecided. The pilot's own rules stop the work at these gates rather than route around them.

04//Rules of the workspace

how claims are kept honest

Small rules, applied every time.

Aggregates only. Audits read public files in memory and publish counts, hashes and provenance. Patient-level records, scores and linkage maps never enter the repository.

Labels before numbers. Anything not independently verified is labelled as such, in the registries and on this page. A reproduced number and a printed reference value are never presented as the same kind of fact.

Fixed before run. Numerical checks are specified, with their tolerance, before they are executed. A disappointing result is recorded unchanged, not tuned away.

Plain tools. Every check runs on the Python standard library alone, so anyone can rerun it: python3 tools/validate.py and python3 -m unittest discover -s tests in the repository.
