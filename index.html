00//The question

Chowdhury et al., Cell 2023

One published result, rebuilt from scratch.

High-grade serous ovarian cancer (HGSOC) is the most common and most lethal form of ovarian cancer. First treatment is usually platinum chemotherapy. The study behind this project compares two deliberately extreme groups. Refractory tumours showed persistent or growing disease on imaging after six cycles of first platinum/taxane chemotherapy. Sensitive tumours did not progress for at least two years. This is primary platinum-refractory disease, and it is not the same as cancer that responds first and resists later.

In 2023, Chowdhury and colleagues published a proteogenomic study of HGSOC. Among its results was a signature: levels of 64 proteins, measured in tumour tissue, that separated refractory from sensitive cancers in the study's own data. The headline measure was an AUC of 0.83. AUC is a ranking score: 1.0 ranks every refractory tumour above every sensitive one, and 0.5 is no better than chance. At the study's strictest operating point it caught about a third of refractory tumours (sensitivity 0.35) while almost never flagging a sensitive one (specificity 98%).

A result like that matters only if it survives outside the data it was built on. Project Asma's first pilot takes the published panel exactly as printed and asks whether the reported numbers can be recovered from the public data, and whether the patients counted as a separate validation group really are separate. It does not build a new test, and it makes no claim about patient care.

02//Still missing

recorded on main · 2026-10-29

Gaps recorded before any fit on study data.

The fold helper

The authors' scripts call a helper file, balanced_folds.R, that decides how patients were split into folds. The searches so far did not find it: the authors' repository at the commit checked, its reachable history and three public forks. A later public repository from the same GitHub account defines a helper of the same kind. It is a likely stand-in, not proof: its 2023 version, shuffle details and the original label order remain unknown. The main branch declares a replacement fold rule. A rerun with it would be a new reconstruction, not a faithful rerun of the printed cross-validation.

The workspaces and processing history

The figure scripts load saved R workspaces (RData files) that the same searches did not find. Which objects they held, and in what order, decides what the printed figure actually averaged. The declared reconstruction starts from the released matrix instead and does not recover them. How that matrix was itself processed (normalisation, filtering, batch correction, imputation) is only partly documented. So even the declared reconstruction cannot claim that every processing step was fitted only inside training folds.

The corrected legends

A 2024 correction fixes the supplemental figure legends only; Figure 3D is outside its stated scope. The supplement copy pinned here predates the correction, and its legends disagree with the figure images at several points. The corrected legends have not been pinned yet, because the publisher's hosts were unreachable from the research environment.

People and permissions

No gynaecologic oncologist or proteomics/biostatistics collaborator has been recruited. Recruiting needs a new explicit instruction. The repository licence is undecided, and external scientific review is pending. Downloading study files for a research run, a real-source input check or any fit on study values needs the owner's dated attestation of the execution context and a new explicit instruction. Clinical interpretation and validation need domain review first.

03//Rules of the workspace

how claims are kept honest

Small rules, applied every time.

Aggregates only. Audits read public files in memory and publish counts, hashes and provenance. Patient-level records, scores and linkage maps never enter the repository.

Labels before numbers. Anything not independently verified is labelled as such, in the registries and on this page. A reproduced number and a printed reference value are never presented as the same kind of fact.

Fixed before run. Numerical checks are specified, with their tolerance, before they are executed. A disappointing result is recorded unchanged, not tuned away.

Offline checks. python3 tools/validate.py and python3 -m unittest discover -s tests run on the Python standard library, plus git in a checkout, without network access. They check the repository's records and test the audit code, the source adapter and the runtime tooling on small made-up inputs. They do not rerun any audit or the published-score check, and passing them is not a scientific reproduction. The R pipeline tests run separately, on artificial fixtures in a pinned Docker container with networking off; the synthetic validation lists the commands. That container has not yet been checked on an actual research host. Separate network commands, listed in the README, rerun the audits. They follow the bounded-inspection rule: in memory, aggregates only, with a record of what was read and why. Neither the R tests nor the network commands are part of the offline checks. The published-score check ran under a recorded instruction, described in its protocol.
